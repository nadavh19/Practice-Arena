# Practice Arena Prototype

Practice Arena is currently a working Next.js 16 prototype for generating and tracking personalized guitar practice sessions. The app is organized around a simple learner flow: a user signs up or logs in, completes a profile, generates a focused practice session, marks completed tasks, submits feedback, and reviews previous sessions. The first screen redirects users based on authentication and profile state: unauthenticated users go to `/auth`, users without a nickname go to `/profile`, and onboarded users go to `/session/new`.

The frontend is implemented in the Next.js App Router under `app/`. Public authentication lives at `/auth`, while the protected area contains `/profile`, `/session/new`, `/session/current`, and `/history`. Protected pages share a client-side shell with navigation, logout, and page-specific visual backgrounds. Authentication is handled with JWTs returned by the API and stored in browser `localStorage`; the shared client API helper attaches the bearer token to requests and clears local auth state on unauthorized responses. The UI has been built out beyond raw forms, with reusable components for page shells, cards, headings, form fields, buttons, selects, and inline status messages.

The backend API is also inside the App Router under `app/api/`. It exposes endpoints for signup, login, profile read/update, session generation, session completion, session history, session stats, and a database connectivity test. Routes are intentionally thin: they parse requests, validate input, check authentication, call service functions, and return a consistent response envelope. Business logic lives in `services/`, while pure recommendation logic lives in `algorithms/`. 

Persistence is handled through Prisma with PostgreSQL. The current schema includes users, sessions, tasks, session-task joins, and feedback. Users store email, hashed password, nickname, instrument, level, and goals. Tasks include guitar-specific practice metadata such as category, duration, difficulty, key, BPM, tab, chords, scale, song name, and artist. Sessions store mood, available time, optional session goal, selected tasks, completion state, and feedback ratings.

The session generator is deterministic and rule-based. It maps the user's level to a target difficulty, splits available time into 5-minute blocks, selects one longer task when possible, then fills remaining time with 5-minute tasks. Task scoring considers difficulty match, current mood, session goal, profile goals, recent feedback, and category variation. Recent feedback can nudge difficulty easier or harder, and low focus ratings bias future sessions toward simpler categories. There is a focused algorithm test suite covering time filling, mood behavior, goal priority, feedback adjustment, and deterministic output.

Feature-wise, the prototype currently supports the main end-to-end loop. A user can create an account, log in, edit their profile, generate a session from mood/time/goal inputs, view task details, select completed tasks, submit difficulty and focus ratings, and view history with aggregate stats such as total sessions, average ratings, and completion rate. The current scope is guitar-only, and the profile update path keeps the instrument locked to guitar.

The main remaining prototype limitations are mostly product-hardening items rather than missing core flow. Auth uses browser `localStorage` instead of cookies or server-backed sessions, so protected routing is client-side. The recommendation engine is transparent and testable but not machine-learning based. Task quality depends on seeded database content, and the history/current-session experience uses the stored current session id plus session history rather than a richer active-session model. Even with those constraints, the app is in a coherent prototype state: the UI, API, database, and recommendation logic are connected and can demonstrate the intended practice-planning workflow.
